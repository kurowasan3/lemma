# 学習記録の保全（v0.23）

学習記録を失わないための仕組み。実装は `js/store.js`（保存・移行・点検・バックアップ・合わせ方）、
`js/sync.js`（通信）、`js/app.js`（画面からの呼び出し）。テストは `tests/store.test.mjs`・`tests/sync.test.mjs`・`tests/e2e.mjs`。

## 1. 保存しているもの

| 保存先（localStorage のキー） | 中身 | 同期 | バックアップ |
|---|---|---|---|
| `lemma.v2` | 学習記録の本体（下の表） | する | 含む |
| `lemma.snap.v1` | 自動の控え（最大2件。移行・読み込み・消去の前の `lemma.v2` の文字列） | しない | 含まない |
| `lemma.v2.broken.<時刻>` | 読めなかった記録の退避（元の文字列そのまま） | しない | 含まない（設定から個別に書き出せる） |
| `lemma.session.v1` | 中断した演習（14日で捨てる） | しない | 含まない |
| `lemma.auth` | ログイン情報（トークン） | — | 含まない（安全のため） |

IndexedDB・Cookie は使っていない。サーバー（Supabase）は表 `lemma_state` に1人1行（`state` に `lemma.v2` と同じ形、`rev` に版番号）。

`lemma.v2` の中身（schema 4）：

| キー | 形 | 意味 |
|---|---|---|
| `log` | `[{ p, t, g, ok?, sg?, c?, h?, min?, in?, md?, k?:'t', r?:1〜3, note?, disp?, feel? }]` | 解答の記録。`p` 問題ID・`t` 時刻(ms)・`g` 評価1〜4。**`(p, t)` が1回の解答の識別子** |
| `pstat` | `{ 問題ID: { S, D, last, reps, lapses } }` | 問題ごとの復習状態（`scheduler.js` `review()`） |
| `problems` | `{ 問題ID: { last, n } }` | 最後に解いた時刻と回数 |
| `cards` | `{ 解法カードID: { S, D, last, reps, lapses } }` | 解法カード（`js/content.js` の CARDS）の復習状態 |
| `bookmarks` | `{ 問題ID: { on, t } }` | ブックマーク（外すと `on:false` を残す） |
| `explains` | `{ 問題ID: [{ t, text }] }` | 気づきのメモ（問題ごとに新しい5件） |
| `streak` `drill` `csvExportedAt` | | 連続日数・計算トレーニングの自己ベスト・CSV書き出し時刻 |
| `settings` `practice` `graph*Exprs` `settingsAt` | | 設定（最後に変えた方を採る） |
| `resetAt` | 時刻 | 「すべて消す」「置き換え」をした印（同期で古い記録を持ち込まない） |
| `schema` `lv0` | | 記録の形の版・移行済みの印 |

解法（Technique）の習熟は `log` から毎回計算する（`mastery.js`）ので、保存していない。
問題ID・解法IDは変えない（`tests/golden/ids.txt`・`techniques.txt` で検査）。

## 2. ローカル保存（`createStore().save()`）

1. 構造の確認（`structural()`：`log` が配列で各要素に `p` と数値の `t`、ほかの入れ物がオブジェクト）。正しくなければ保存しない。
2. **別のタブの書き込みの確認**：保存されている文字列が、このタブが最後に読み書きしたものと違えば、別のタブ（同じ端末の別の画面）が保存したので、`mergeState` で合わせてから保存し、合わせた結果を画面の記録にも入れる。
3. `localStorage.setItem`。失敗（容量・プライベートモード）しても**前の値のまま残る**（setItem は全部書くか何もしないか）。画面に1回知らせる。
4. 書いた内容を読み返して長さを確かめる。

5000件での切り捨ては v0.23 でやめた（同期のたびに古い記録が消えていた）。

## 3. 読み込み（起動時の `load()`）

| 状態 | 処理 |
|---|---|
| 何も無い | 新しい記録 |
| JSON として読めない | 元の文字列を `lemma.v2.broken.<時刻>` に退避して、新しい記録で始める。退避もできなければ**本体への保存を止める**（元の記録を上書きしない） |
| 一部の形が壊れている | 元を退避し、壊れた入れ物だけ初期値にして、ほかの記録（解答の記録など）は使う |
| 古い schema | 移行（§4）。移行の前に控えを残す |
| 新しい schema（新しい版のアプリの記録） | 移行せず、知らない項目も残してそのまま使う。画面に知らせる |

いずれも起動時にバナーで知らせ、設定の「学習記録のバックアップ」から退避した記録を書き出せる。

## 4. schema と移行

- 今の版：`SCHEMA = 4`。読める最も古い版：`MIN_SCHEMA = 1`（v0.1）。schema の無い記録は 1 とみなす。
- `MIGRATIONS`：版ごとの手順（`from` → `from+1`）。`PATCHES`：版を変えない正規化（`lv0`：v0.6 で「基礎」を選択に足す）。
- 各手順はコピーに対して動く純関数で、何度実行しても同じ（`migrate(migrate(x).state)` は何もしない＝二重の移行をしない）。
- 移行の後に構造を確かめる。途中で失敗したら例外になり、**本体の元の記録は変えない**（退避もする）。
- schema 1〜3 → 4 は演習の「選択」（分野・難易度）だけを初期化する。解答の記録・復習状態は変えない。
- schema を上げるとき：`SCHEMA` を上げ、`MIGRATIONS` に `{ from: 旧, up }` を足し、`tests/store.test.mjs` に旧版の記録を足す。
  古い版のアプリは新しい schema の記録を移行しない・同期で上書きしない（§6）が、v0.22 以前のアプリはこの確認を持たない。

## 5. バックアップと復元

書き出し（設定の「書き出す」）の形：

```json
{ "format": "lemma-backup", "version": 1, "app": "0.23.0", "schema": 4,
  "createdAt": "2026-11-23T…Z", "counts": { "log": 1234, "pstat": 300, … },
  "hash": "fnv1a32:xxxxxxxx", "state": { …lemma.v2 と同じ… } }
```

- 含む：§1 の `lemma.v2` の全部。含まない：控え・退避・中断した演習・ログイン情報。
- `hash` はキーの順によらない JSON（`stable()`）の FNV-1a。壊れた・途中で切れたファイルを見分けるためで、改ざん防止ではない。
- v0.22 までの書き出し（記録そのもの）も読める（`version` 0 として扱う）。

読み込み（`readBackup()` → `restoreState()` → `store.replace()`）：

1. JSON として読めるか、`format`・`version`（新しすぎれば拒否）・`hash`（合わなければ拒否）を確かめる。
2. 構造・schema（新しすぎれば拒否）を確かめ、古ければ移行する。
3. 点検（§7）でエラーがあれば拒否（理由と対象のIDを表示）。注意は受け付けて表示する。
4. 「合わせる」か「置き換える」を選ぶ。設定は今のものを残す。置き換えでは `resetAt` を付ける。
5. 結果を点検し、エラーがあれば取りやめる。
6. **今の記録を控え（`lemma.snap.v1`）に残し**、控えを残せなければ今の記録をファイルに書き出してから、保存する。
7. 保存に失敗したら本体を元に戻し、画面の記録も変えない（ロールバック）。
8. 件数の変化と点検の結果を表示する。

控えへの復帰（設定「自動の控え」→「戻す」）も同じ手順。「記録をすべて消す」も控えを残す。
ただし「ログアウトしてこの端末だけ消す」は共用端末のため控えを残さず、**サーバーへ同期できたことを確かめてから**消す
（ログアウト時の「この端末の記録も消す」も同じ）。控えは「控えを消す」で消せる。

## 6. 同期（Supabase）

1回の同期（`syncOnce()`）：サーバーの行を取る → 確かめる → 手元と合わせる → 違えば `rev` つきで書き戻す（版がずれていれば取り直して最大4回）。

- サーバーの記録の形が正しくない・新しい schema のときは、合わせず書き戻さず止める（手元もサーバーも変えない）。手元の記録の形が正しくないときは送らない。
- 一時的な失敗（オフライン・同時の書き込み・408/429/5xx）は 15秒・30秒・60秒・120秒あけて自動でやり直す。形の問題・ログイン切れはやり直さない。
- 書き戻しの途中で通信が切れても、サーバーは前の `rev` のまま（PATCH は1行の更新）。次の同期で合わせ直す。
- 通信している間にこの端末で解いた分：反映の前に今の記録ともう一度合わせる（`app.js` `applyState`）ので失われない。

合わせ方（`mergeState`、どちらから合わせても同じ・何度合わせても同じ）：

| 項目 | 規則 |
|---|---|
| 解答の記録 | 和集合。`(p, t)` が同じものは1つにし、片方にしか無い項目は足す。切り捨てない |
| 復習状態 | 片方にしか無ければそれ。両方にあって `last` が違うとき、古い方の `last` より後の解答の記録が、新しい方の `reps` の増え方より多ければ（＝2台で別々に復習した）、古い方から記録を時刻順に `review()` し直す。そうでなければ新しい方。同じ `last` なら `reps` の多い方 |
| 解いた問題 | 最後の時刻は新しい方、回数は多い方（記録の数以上） |
| 解法カード・ブックマーク | 新しい方（ブックマークは外した印も残す） |
| メモ | 和集合（問題ごとに新しい5件） |
| 設定 | `settingsAt` が新しい方 |
| `resetAt` | 新しい方。印の古い側からは、その時刻より前の記録を持ち込まない |

時刻だけで決めているのは設定・解法カード・ブックマークだけ。学習の記録（解答・復習状態）は、時刻の比較だけで片方を捨てない。

## 7. 整合性の点検

`audit(state, { problemIds, cardIds, now })` → `{ errors, warnings, stats }`。各項目に `code`・説明・対象のID（最大50）・件数・`fix`（`auto`＝`repair()` で安全に直せる／`human`＝人が判断）。

| 区分 | code |
|---|---|
| エラー | `bad_container` `bad_log` `bad_schema` `log_bad_time`（2020年より前）`log_bad_grade` `log_bad_recall` `pstat_invalid`（S≦0、D が1〜10の外、lapses>reps など）`card_invalid` `problems_invalid` `bookmark_invalid` `explain_invalid` `reset_invalid` `settingsat_invalid` |
| 注意（auto） | `log_duplicate` `log_unsorted` `problems_behind_log` |
| 注意（human） | `log_unknown_problem` `pstat_unknown_problem` `bookmark_unknown_problem` `card_unknown`（今のデータに無いID）`log_future` `reset_future` `log_bad_kind` `streak_invalid` `schema_newer` |

`repair()` は削除しない：重複した解答の記録の統合（項目は足すだけ）・時刻順の並べ替え・解いた回数の引き上げだけ。
アプリは自動では直さない（点検の結果を設定に表示するだけ）。

使い方：

```
node tools/audit_state.mjs lemma-2026-11-23.json             # 点検（エラーがあれば終了コード 1）
node tools/audit_state.mjs lemma-2026-11-23.json --json      # JSON で
node tools/audit_state.mjs lemma-2026-11-23.json --fix 直した.json   # 安全な修復をした新しいファイル（元は変えない・既存のファイルは上書きしない）
```

10万件の記録の点検は1秒未満（`tests/store.test.mjs` で確認）。

## 8. 分かっている制約

- localStorage は約5MB。解答の記録は1件 約150〜200字なので、2万件前後で保存できなくなる。そのときは保存を止めて知らせる（前の記録は残る）。IndexedDB への移行は未着手。
- 控えは本体と同じ大きさなので、記録が大きいと控えを残せない（そのときは控えを捨て、読み込み・消去ではファイルに書き出す）。
- v0.22 以前のアプリが同じアカウントで同期すると、そのアプリの合わせ方（5000件で切り捨て・復習状態は新しい方だけ）でサーバーの記録が書かれる。全端末を v0.23 に更新する必要がある。
- 端末の時計が大きくずれていると、`last`・`settingsAt`・`resetAt` の比較が狂う（未来の時刻は点検で注意になる）。
- 「ログアウトしてこの端末の記録も消す」をした端末で、別のタブが古い記録を開いたままだと、そのタブの次の保存で記録が戻ることがある（消した印を付けないため）。
- バックアップの `hash` は改ざん防止ではない。
- Safari は7日以上開かないとサイトの保存領域を消すことがある（ホーム画面に追加すると対象外）。これはアプリでは防げない。
