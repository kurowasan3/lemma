# Lemma 改善計画（2026-11、v0.15.3 時点の調査にもとづく）

「良質な問題を、最適な順序と適切な反復で学び、解法を自分のものにする」ための改善計画。
S＝最優先、A＝重要、B＝将来対応。各項目に 現状／問題点／改善内容／理由／コスト／効果 を書く。
**v0.16.0 で実装** と書いたものは実装済み。

## 調査で分かった現状（要点）

- 構成：素の ES モジュールの PWA。`content/`（正規データ）→ `tools/build_app_data.py` → `data/`（分野ごとの本文ファイル＋索引）。Supabase は記録の同期だけ（`lemma_state` 1表、RLS は本人のみ読み書き）。テストは `node tests/run.mjs --e2e`（データ監査・採点・同期・Playwright の通し操作・CSP つき dist）を CI で実行。
- 問題：5,278問（管理表 5,216問＋内蔵 61問ほか）。品質状態は `quality.status`（published / hidden）と `checks`（dual・sympy・human）。`human`（人の確認）はほぼ全問 false。
- 解法カード：`content/methods.json` に 45枚。**結びついているのは内蔵の 61問だけ**で、管理表の 5,216問は `idea`（核となるアイデア）とタグだけを持つ。
- 復習：問題ごとに FSRS 風の安定度を持ち、R＜0.9 で復習に出す。自信度（自信なし／たぶん／確実）は記録されるが、復習間隔には「確実で正解」だけが効いていた。
- ホーム（今日）：「全分野からランダム」・復習ボタン・ブックマーク・検索・問題セット・分野一覧・「学び方」の説明が縦に並ぶ。**中断した演習は再開できない**（タブを閉じると消える）。連続日数を表示していた。
- 解答後：判定 → 解答・解説（核となるアイデア・タグ）→ 手応え → 一言メモ → 次へ。類題へ進む手段はない。
- 定着度：分野・科目の得意度（3問以上で表示、0.5 へ縮める補正あり）、自信と結果のズレ。最近の伸びは見えない。
- 検索：全文＋タグ辞書、難易度で絞り込み、v0.15.3 で頻出度・難易度の並べ替え。解いた状態（未着手・間違えた・復習待ち・ブックマーク）では絞れない。

## S（最優先）

### S1 「今日」を学習の司令塔にする — v0.16.0 で実装
- 現状：入口が多く（ランダム・復習・セット・分野）、毎回どれから始めるか選ぶ必要がある。中断した演習は再開できない。
- 問題点：「開く → すぐ勉強」にならない。復習を忘れやすい。連続日数の表示は理念（煽らない）に合わない。
- 改善：画面の一番上に「今日の学習」。今日解いた数／目標（1回分の問題数）、**前回の続き**（中断した演習を何問目からでも再開）、**今日の演習を始める**（復習待ちを先に、残りを新しい問題で埋め、データが十分な苦手分野から最大2問を混ぜる）を1ボタンで。苦手分野の提案（根拠の回答数つき）。連続日数の表示はやめ、「学び方」は折りたたむ。
- 理由：何をやるかの判断をアプリが引き受け、学習者は解くことに集中できる。
- コスト：小（app.js と catalog.js。記録の形式は変えない。中断の情報は端末内だけに保存）。
- 効果：開始までの操作が1タップに。復習の取りこぼしが減る。

### S2 解答後の流れ（自信度×正誤で復習を決める・類題へ） — v0.16.0 で実装
- 現状：自信度は記録されるが、「正解だが自信なし」も通常の間隔。「確実なのに不正解」に何の指摘もない。類題に進めない。
- 改善：
  - 正解＋自信なし → 「ヒントあり」と同じ短い間隔（早めに復習）
  - 不正解＋確実 → 「思い込みの可能性」の注意を出し、核となるアイデアを先に読ませる
  - 「類題を1問追加」：同じ分野・近い難易度・共通タグの多い未着手（なければ久しぶり）の問題を次に差し込む
- 理由：自信度を復習の優先度に反映すると、わかったつもりの問題が早く戻ってくる。類題で同じ技法を続けて使うと、解法が定着する。
- コスト：小。入力操作は増やさない（自信度は既存の1タップ）。
- 効果：誤概念の早期発見、技法の定着。

### S3 習熟度の表示を慎重にする — v0.16.0 で実装
- 現状：3問で得意・苦手を色分けしていた。最近の伸びは見えない。
- 改善：得意度は 5問以上で表示し、10問未満は「暫定」と明示。最近14日とそれ以前の完答率を、どちらも10回以上あるときだけ比べて表示。
- 理由：少ない回答で「得意」と断定しない。次の行動（苦手分野の演習）を明確に。
- コスト：小。

### S4 管理表の問題に解法（技法）を結びつける — v0.17.0 で第1段を実装
- 現状：解法カード 45枚は内蔵 61問だけに結びつく。5,216問は `idea` とタグだけ。
- 問題点：解法を軸にした学習（解法ごとの問題一覧・習熟・間違えた問題）が、大半の問題でできない。
- 改善：まず**タグ辞書（`content/tags.json`）を「技法タグ」と「分野・話題タグ」に分け**、技法タグを解法カードに昇格させる（概要・本質・使う場面・発想の起点・前提・関連解法を人が書く）。問題には既存のタグから自動で候補を付け、管理表の列で確認・修正する。アプリには「解法」ページ（説明・難易度別の問題・自分の習熟・間違えた問題・関連解法）を作り、解説のタグから飛べるようにする。
- 理由：Lemma の中核資産。ただし説明文は数学的に正確である必要があり、自動生成で公開しない（理念 9）。
- コスト：大（内容の執筆と確認が中心）。コードは中。
- 効果：解法を体系として学べる。復習の単位を「問題」から「解法」に広げられる。
- v0.17.0 で実装したこと：
  - 解法カード 75枚（`content/techniques.json`。9分類：式と方程式・不等式と最大最小・整数・場合の数と確率・数列・極限と微分積分・図形とベクトル・複素数平面と2次曲線・論証）。各カードに概要・本質・使う場面・発想の起点・前提・関連。
  - 結びつけ：カードの `tags` に書いたタグ（正規名・別名）をもつ問題を自動で結ぶ（4,394 / 5,216問）。あいまいなタグ（「因数分解」「交点」「周期」など、別の意味でも使われるもの）は外した。管理表の「解法」列で問題ごとに指定でき、指定があればそれを優先。
  - アプリ：解法の一覧（分類別・検索）、カードのページ（説明・自分の習熟・間違えた問題の解き直し・難易度別の問題と演習）、解説の「この問題の解法」、検索結果の上に解法カード、定着度の「解法ごとの習熟」。
  - 監査：カードの参照先・空欄・管理表の「解法」列の名前を検査。カードの数式も KaTeX で検査。
- 残り：カードの文章の人による確認（`reviewed`）。結びついていない約800問（タグが話題だけのもの）は、管理表の「解法」列で指定していく。復習の単位を「解法」に広げるのは、結びつきの精度を確かめてから。

## A（重要）

### A1 検索で学習状態を絞り込む — v0.16.0 で実装
- 現状：難易度でしか絞れない。
- 改善：「すべて／未着手／間違えた／復習待ち／ブックマーク」の絞り込みを1つの選択に（詳細条件を最初から並べない）。
- コスト：小。効果：間違えた問題・ブックマークの再演習が検索からできる。

### A2 品質管理の状態を細かくする
- 現状：`quality.status` は published / hidden、`checks.human` はほぼ全問 false。
- 改善：既存の形式を壊さずに、status に `draft / checked / reviewed / published / rejected` を足す（published と hidden はそのまま有効）。管理表の「状態」列、`audit_data.py` に「人の確認がない入試発展以上の問題」「idea が空」「解説が短すぎる」「重複候補」などの一覧を出す。アプリは published だけを出す（今と同じ）。
- 理由：問題の質が価値の源泉。確認の進み具合を数えられるようにする。
- コスト：中（スキーマ・取り込み・監査。アプリはほぼ不変）。

### A3 編集した問題セットを教材にする
- 現状：問題セットは 6つ（ID の並び＋説明）。
- 改善：セットに「対象レベル・身につく技法・順番の意図」を持たせ、表示する。S4 の解法ができたら「漸化式の解法体系」「ベクトルの典型技法」などを解法順に編む。
- コスト：中（大半は編集作業）。

### A4 間違えた問題の一覧と「解き直し」
- 現状：間違えた問題は復習に混ざるだけで、一覧では見られない（A1 で検索から絞れるようになった）。
- 改善：定着度ページに分野ごとの「解き直し待ち」を出し、そこから演習できるように。

## v0.21.0：判定の整合性・監査の入力検証・推薦の境界条件

- 保持：問題ごとの復習の記録（pstat）が1つも無いと「今も覚えている」を満たしたことになっていた誤りを修正。保持は「はい／すべて解き直しの時期を過ぎている／確認できない」の3つで、確認できないときは習得にしない。
- 表示：「転用」の段階を「異なる文脈の問題で完答」「…・解法の想起も自己申告あり」「異なる文脈の問題はまだ未確認」「判定できる問題がない」に。「転用できた」「応用力が身についた」とは書かない。
- 監査：人の記入は OK・要修正・×・空欄だけを受け付け、それ以外は警告して確認済みにしない。存在しない問題 ID は誤り、重複行と内容が変わった行（照合用の値）は確認済みにしない。優先順の頻出度を data の値（自動判定を含む）で並べるよう修正、短い問題文の類似は優先1から外す。
- 推薦：未着手が尽きたときに直前に解いた問題を「新しい問題」として出していた誤りを修正（3日以内に解いた問題は出さない・理由を「解いてから日がたった問題」に）。足りないときは制限を越えずに少ない数で出し、理由を表示。境界条件のテストを追加。

## v0.23.0：学習記録の保全と復旧

- 保存・移行・点検・バックアップを `js/store.js` にまとめた（合わせ方 `mergeState` も sync.js から移し、sync.js は再公開）。仕様は `docs/data-integrity.md`。

- 同期：サーバーの記録を確かめてから合わせる。一時的な失敗は自動でやり直す。2台で別々に復習した問題の復習状態を両方反映。5000件での切り捨てをやめた。通信中に解いた記録を落とさない。ログアウトして消すときは同期できたことを確かめる。
- 点検ツール `tools/audit_state.mjs`。テスト `tests/store.test.mjs`（78件）と、同期・e2e の追加。

## v0.24.0：保全機構の境界条件・競合・復旧

- 新しい schema の記録を上書きしない：読み込んだら保存・置き換え・同期を止める（画面では使う）、保存する記録・保存されている記録・別のタブの記録の schema も確かめる。schema を上げるときは保存先のキーも変える決まり（テストで検査）。
