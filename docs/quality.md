# 問題の品質管理

問題は消さない・自動で書きかえない。自動で確かめられることは道具で一覧にし、数学的な正しさの判断は人が行う。
**自動検証に合格したことを、人による数学的確認と同じには扱わない。** 品質の点数は作らない。

## 1. 品質の状態（自動と人を分ける）

品質の記録は学習記録とは別のファイルに置く（`content/quality/`）。どちらも、確かめた時点の**内容の照合用の値**（問題文・答え・解説・核となるアイデアから作る12桁の値）を持つ。あとで問題が直されると値が変わり、その記録は「古い」と扱う（合格・完了とはみなさない）。

| 種類 | 状態 | 意味 |
|---|---|---|
| 自動検証（`content/quality/auto.json`、`tools/verify_math.py --write`） | 未実行 | 記録が無い |
| | 合格（答えの値） | 照合できたすべての小問で、答えの値が計算し直した値と一致 |
| | 一部の小問だけ確認 | 一部の小問だけ照合できた、または「答えは条件を満たすが、すべてかは未確認」 |
| | 不一致あり | 計算し直した値と答えが合わない小問がある |
| | 対象外 | 自動では照合できない（証明・説明・図形・場合の数・読み取れない形 など） |
| | 記録が古い | 記録のあとで内容が変わった |
| 人の確認（`content/quality/human.json`、`tools/audit_problems.py --reviewed … --record`） | 未実施 | 記録が無い |
| | 完了 | 9項目すべて OK |
| | 要修正 | 要修正・× が1つ以上 |
| | 記録が古い | 確認のあとで内容が変わった |
| | 管理表で済（内容の照合なし） | 管理表の「検証:人間確認」が「済」だが、どの内容を確認したかの記録が無い |

記録には、問題 ID・項目（自動は小問と種類、人は9項目）・日付・方法（自動はツールの名前と版、人は記入の方法）・結果・照合用の値を残す。

管理表の「検証:二重解答」「検証:SymPy等」は、問題を作ったときの**申告**（リポジトリの外で行ったもの）で、問題データの `quality.checks.dual`・`checks.sympy` に入る。リポジトリの自動検証（`auto.json`）とは別に扱う。今は全問が「検証:SymPy等＝済」だが、リポジトリで答えを計算し直して照合できたのは下の範囲だけ。

## 2. 自動検証（`tools/verify_math.py`）で確かめられること・確かめられないこと

**確かめられること**（小問ごと。式が数で決まり、読み取れる形のときだけ）

| 種類 | 方法 |
|---|---|
| 定積分 | SymPy で積分し、答えの値と照合 |
| 極限 | SymPy の `limit` と照合 |
| 漸化式の一般項 | 答えの式が初項（と第2項）と漸化式を満たすかを記号計算で確認（記号計算で 0 にならなければ n=1〜12 の値で照合し「数値で一致」） |
| 方程式の解 | SymPy で解の集合を求めて照合。求まらなければ、答えの値が方程式を満たすかだけ（「すべての解かは未確認」） |

結果は「記号計算で一致」「数値で一致（証明ではない）」「答えは条件を満たす（すべてかは未確認）」「不一致」「対象外」で残す。比べられない値（数値にできない・時間切れ）は不一致にせず対象外にする。

2026-11-23 の実行で照合できたのは 82問（合格 31・一部の小問だけ 51）、不一致 0、対象外 5,134問。対象外が大半なのは、証明・図形・場合の数・文字を含む答えなど、答えの値を機械的に計算し直せない問題が多いため。

**確かめられないこと**

- 解答の論理（飛躍・必要条件と十分条件の取り違え・場合分けの網羅・定義域や例外の見落とし）
- 解説の十分さ・再現できるか・その解法を選ぶ理由
- 問題文の条件の不足・矛盾・答えの一意性（下の構造の検査は「候補」を出すだけ）
- 数値で一致しても証明ではない。答えの値が正しくても解説が誤っていることがある

**構造の検査**（数学的な検証ではなく、形の不整合の候補。2026-11-23 の実行で 80問）

- 答えの無い小問（図示などで答えを書いていない、または答えの抜け）
- 小問の数より多い番号が答えにある（小問の区切りの誤り。例：`\item` の中に「(2)」を書いてしまった問題）
- 小問があるのに答えが小問ごとに分かれていない
- 要求（求めよ・示せ・表せ・空欄 など）が読み取れない
- 答えに、問題文にも解説にも無い文字が出てくる（条件不足・記号の未定義の候補）

## 3. 人による確認の基準

`quality.csv` の【人】の9項目に、**OK**（問題なし）・**要修正**（修正が必要）・**×**（問題あり）だけを書く。空欄は未確認。それ以外の値（「ok」「○」「済」など）は警告して確認済みにしない。

| 項目 | 見ること |
|---|---|
| 数学的正確性 | 問題文に矛盾がない・定義域や範囲が適切・答えが一意に定まる（必要な場合） |
| 問題文の明確さ | 条件の不足がない・記号と用語の定義が明確・要求が問題文と整合 |
| 解答の正確性 | 計算結果・論理の飛躍がない・必要十分・場合分けの網羅・例外の見落としがない・要求に答えている |
| 解説の十分性 | 根拠・重要な変形と推論が省略されていない・その解法を選ぶ理由・再現できる・必要なら別解 |
| 難易度の妥当性 | 難易度の段階（基礎〜数学探究）に合っている |
| 教育的価値 | 何を習得させるかが明確 |
| 他の問題との差別化 | 既存の問題と学習目的が過度に重複していない（`role.csv`・`similar.csv` を参考に） |
| 分類・タグの妥当性 | 主な解法・補助の解法・タグが合っている |
| 収録する価値 | 基礎・標準なら反復する価値、発展なら新しい考え方や組み合わせを学べるか |

## 4. 類似問題と、学習上の役割の重複

`python3 tools/audit_problems.py --csv DIR` が書き出す。どれも**候補**で、削除・統合はしない。

- `similar.csv`：問題文の文字列の類似（同一・数値違い・4-gram の Jaccard ≥ 0.7）。短い問題文（数字を置きかえて60文字未満）は定型の言い回しだけで似やすいので「短い」と印を付け、優先1に入れない。数字を含めた類似度も並べる。
- `role.csv`：**学習上の役割が近い候補**。主な解法・難易度・要求（値・証明・個数・確率・最大最小・範囲・図示）が同じで、核となるアイデアか出題テーマが近い組（3文字の重なりの Jaccard がアイデア 0.5 以上かテーマ 0.6 以上）。主な解法・補助の解法・アイデア・テーマ・難易度・要求・役割（基礎の反復／標準解法の習得／解法の応用／挑戦）を並べて比べられる。
  - 同じ解法を使う問題を一律に重複扱いしない：アイデアもテーマも違う（違う条件・着眼点・応用先を学べる）組は出さない。
  - 文章や数値が違っても、アイデアが同じなら候補に出る（文字列の類似では見つからない組）。
  - 基礎・標準は反復のために似た問題が必要なこともある。残すかは人が決める。基礎・標準の問題が少ないことは欠点として扱わない。

## 5. 優先して確認する問題（`priority.csv`）

確認の順序であって品質の点数ではない。1問1行、挙がった理由をすべて書く。

- 優先1：自動検証で不一致・人の確認で要修正・同一の問題文・数値だけ違う問題文・類似度 0.9 以上（短い問題文を除く）
- 優先2：構造の候補・解答／解説／核となるアイデアのどれかが無い
- 優先3：主な解法が決まっていない（入試基礎以上）・管理表の申告で自動検算が未実施・自動検証や人の確認の記録が古い
- 優先4：同じ主な解法・同じ難易度に類似候補が集まっている・学習上の役割が近い候補

同じ優先度の中は頻出度の高い順・難易度の低い順。人の確認が完了した問題（記録か管理表の「済」）は優先2〜4から外す。

## 6. CSV の操作

1. `python3 tools/audit_problems.py --csv DIR` で `quality.csv` などを書き出す。
2. `quality.csv` を Excel などで開き、確認した問題の【人】の9項目に記入する。ほかの列（特に「内容の照合用（変えない）」）は変えない。列の順番は変えてもよい。保存は CSV（UTF-8。BOM はあってもなくてもよい）。
3. `python3 tools/audit_problems.py --reviewed 記入したquality.csv --csv DIR` で照合する。
   - 誤り（終了コード 1）：必要な列が無い（記入の有無より先に調べる）・同じ名前の列が複数・列の数が見出しと合わない行・存在しない問題 ID
   - 警告（その問題は確認済みにしない）：使えない値・同じ問題 ID が複数行・内容の照合用の値が今のデータと違う（記入後に問題が直された・古い CSV）
   - 空行は無視する
   - `reviewed.csv`：管理表の「検証:人間確認」を「済」にしてよい問題・直す問題・確認途中の問題
4. 照合に誤りが無ければ、`--record` を付けて実行すると、完了と要修正の結果を `content/quality/human.json` に記録する（管理表・問題データは書きかえない）。管理表の「検証:人間確認」は人が `reviewed.csv` を見て更新する。

## 7. テストで毎回確かめていること

| 項目 | 道具 |
|---|---|
| ID の重複・消失、必須項目、難易度・分野の値、タグ辞書 | `tools/audit_data.py` |
| 入力採点の答えが読めて、正解を入れると正解になる | `tools/check_answers.mjs` |
| すべての数式が描画できる | `tools/check_katex.cjs` |
| 解法カードと問題の結びつき（参照・循環・ID の消失） | `tools/audit_techniques.py` |
| 自動検証の記録が今のデータと合っているか（内容が変わった問題の数） | `tools/verify_math.py --status` |
| 自動検証・品質監査の道具そのもの | `tests/verify_math_test.py`・`tests/audit_problems_test.py` |
