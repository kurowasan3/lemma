# 問題の品質管理

問題は消さない・自動で書きかえない。自動で確かめられることは道具で一覧にし、判断は人が管理表で行う。

## 自動で確かめていること（テストで毎回）

| 項目 | 道具 |
|---|---|
| ID の重複・消失、必須項目、難易度・分野の値、タグ辞書 | `tools/audit_data.py` |
| 入力採点の答えが読めて、正解を入れると正解になる | `tools/check_answers.mjs` |
| すべての数式が描画できる | `tools/check_katex.cjs` |
| 選択肢・図が問題文と合っている | `tools/make_choices.mjs --check`・`tools/make_figures.mjs --check` |
| 解法カードと問題の結びつき（参照・循環・ID の消失） | `tools/audit_techniques.py` |

## 人が確認するための一覧（必要なときに実行）

`python3 tools/audit_problems.py --csv DIR`

- `similar.csv`：同一・数値違い・類似（文字4-gram の Jaccard ≥ 0.7）の候補。文字列の比較なので、数学的に同じでも表現が違うものは見つからない。
- `quality.csv`：問題ごとに、自動で分かる項目（解答・解説・核となるアイデア・入力採点の答えの有無、解説の長さ、タグの数、主な解法、類似候補の数、自動検算、人の確認）と、**人が判断する項目**（数学的正確性・問題文の明確さ・解答の正確性・解説の十分性・難易度の妥当性・教育的価値・他の問題との差別化・分類とタグの妥当性・収録する価値）の空欄。

- `priority.csv`：**優先して確認する問題**。決まった規則で並べ、各行に挙がった理由を書く（点数は作らない）。優先1＝同一・数値だけ違う・類似度0.9以上（重複していないか）、優先2＝解答・解説・核となるアイデアのどれかが無い、優先3＝主な解法が決まっていない（入試基礎以上）・自動検算が未実施、優先4＝同じ主な解法・同じ難易度に類似候補が集まっている。同じ優先度の中は頻出度の高い順・難易度の低い順。人の確認が済んだ問題は優先2〜4から外す。

人が確認したら、`quality.csv` の【人】の列に記入する（問題なしは「OK」、直す必要があれば「要修正」か「×」）。
`python3 tools/audit_problems.py --reviewed 記入したquality.csv --csv DIR` で、管理表と照合した `reviewed.csv` を作る：
すべて記入済みで「要修正」が無い問題＝管理表の「検証:人間確認」を「済」にしてよい問題、「要修正」がある問題＝直す問題、記入途中の問題。管理表やデータは書きかえない。

注意：
- 類似・数値違いは**候補**で、数学的に同じとは断定しない。数値だけ違う問題や同じ解法の類題は、反復のために必要なことが多く、**消す対象ではない**。残すか、まとめるか、差しかえるかを人が決める。
- 基礎・標準の問題が少ないことは欠点として扱わない（厳選した問題をくり返す方針）。問題を増やすことを目的にしない。

`python3 tools/audit_techniques.py --csv DIR`：結びつかない問題・要確認の自動の結びつき・解法が多すぎる問題。

品質の「点数」は自動では作らない。人が確認した問題は管理表の状態（`quality.checks.human`）で記録する。

## 問題の教育的役割について

「基本」「応用」「融合」「挑戦」などの役割は、新しい項目として全問に付けていない。今のデータから言えるのは、難易度（基礎〜数学探究）、頻出度、結びつく解法の数（2つ以上なら組み合わせ）、その解法にとっての文脈（別の分野・補助）までで、これらはすでに推薦と解法の習熟（転用）に使っている。それ以上の役割を推定で付けると根拠のない分類になるため、付けるなら管理表で人が付ける列として追加する。
