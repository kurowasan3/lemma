# 解法体系（v0.18）

## データ：`content/techniques.json`（schema `lemma.techniques/2`）

| 項目 | 意味 |
|---|---|
| `id` | 解法 ID。変えない。改名・統合で ID を変えたら、移した先のカードの `former` に旧 ID を書く（URL を引き継ぐ。`tests/golden/techniques.txt` で消失を検査） |
| `group` | 分野の分類（9つ）。`groups` を参照 |
| `kind` | 種類：`basic` 基本の技法・`theorem` 定理・公式・`standard` 定石・`strategy` 問題解決の方針・`proof` 論証 |
| `summary` / `essence` / `when` / `cue` / `caution` | 概要・核心・使う場面・着眼点・注意点（すべて必須。`$…$` の数式と `**強調**` が使える） |
| `pre` | **必須の前提**：これを知らないと使えない解法（向きあり。循環は誤り） |
| `rec` | **先に学ぶとよい**解法（向きあり。pre と合わせて循環は誤り） |
| `rel` | **組み合わせて使う**解法（向きなし） |
| `alt` | **同じ問題への別のアプローチ**（向きなし） |
| `tags` | この解法を表すタグ。これらのタグをもつ問題が自動で結びつく |
| `weak` | `tags` のうち、話題を表すだけのタグ。これらからは「補助」としてだけ結ぶ |
| `reviewed` | 人が数学的な正確さを確認したら `true`（`false` の間はカードに「確認を受けていません」と出す） |

画面の「発展」は、他のカードの `pre`・`rec` から逆にたどったもの。「同じ問題によく出る」は、同じ問題に5問以上いっしょに結びつく解法（データから計算。手で書かない）。

## 問題との結びつき（`tools/build_app_data.py`）

- 管理表の「解法」列（名前か ID を読点区切り。旧 ID も可）があれば、それだけを使う。**先頭が主な解法**、残りは補助。
- なければタグから自動で：`weak` 以外のタグで最初に当たった解法を**主な解法**、残りを**補助**とする（タグの並び順を使う推定）。
- `data/techniques.json` に、カードごとの `ids`（すべて）・`main`（主な解法として結びつく問題）・`with`、管理表で指定した問題の一覧 `manual` を書き出す。
- 画面では、主な解法を太字、自動で結びつけたものに「（自動）」と表示する。

## 検査（`python3 tools/audit_techniques.py`、テストで毎回実行）

誤り：ID・名前・旧 ID の重複、参照先の欠け・自己参照、`pre`＋`rec` の循環、種類・分類の値、必須の文章の欠け、以前あった ID の消失、書き出したデータと索引の不整合、管理表の「解法」列の名前の誤り。
警告（人が確認する一覧）：`--csv DIR` で `unlinked.csv`（結びつかない問題）・`suspect.csv`（その解法としては珍しい分野にある自動の結びつき）・`many.csv`（解法が5つ以上の問題）を書き出す。管理表の「解法」列で直す。

## 解法の習熟（`js/mastery.js`）

問題ごとの復習（`scheduler.js`：その問題をいつ解き直すか）とは別に、学習記録から解法ごとに判定する。記録の形は変えず、次の印を付けることがある（どちらも省略可。古い記録はそのまま読める）。

- `k: 't'`：解法カードから始めた演習の回（解法を知らされて解いた）
- `r`：解答後に任意で答える「解法は浮かんだか」。1=すぐ浮かんだ・2=考えるうちに気づいた・3=浮かばなかった／別の方法で解いた。**r が無い回は「未回答」で、想起の成功にも失敗にも数えない**（v0.19 では未回答を成功として扱っていたのを v0.20 で修正）

1つの解法について、問題ごとに次を区別して表示する。

| 区別 | 条件 |
|---|---|
| 解法を知らされずに完答 | 完答した回に `k≠'t'`。ただし `r=3` と答えた回は除く（その解法を使ったと言えないため） |
| 想起を確認（浮かんで完答） | 知らされずに完答し、`r=1,2` と答えた（本人の回答） |
| 浮かばなかったが完答 | 完答し `r=3` |
| 浮かんだが完答できず | 最後の回が完答でなく、`r=1,2` |
| 想起は未回答 | 知らされずに完答したが、想起について一度も答えていない |

### 転用

「違う文脈」は問題データから分かる**代理の指標**で、その解法を実際に使ったことを観測したものではない。

- **主な分野**：その解法を主な解法とする問題が最も多い分野。**同数なら同数の分野すべて**（1分野を勝手に選ばない）
- **文脈の印**：主な分野の問題か、どの別の分野の問題か × ほかの解法も結びつく問題か
- 使う問題：その解法が**主な解法として**結びつく問題だけ（補助として結びつく問題は、その解法を使ったか分からないので使わない。v0.19 では使っていた）

画面では「転用できた」「応用力が身についた」とは書かない。段階の表示は次のとおり。

| 段階（画面の表示） | 条件 |
|---|---|
| 判定できる問題がない | 主な解法の問題の文脈が1種類しかない（習得の条件から外し、そう表示する） |
| 異なる文脈の問題はまだ未確認 | 知らされずに完答した問題の文脈が1種類以下。**力が足りないという意味ではない** |
| 異なる文脈の問題で完答 | 知らされずに完答した問題の文脈が2種類以上。根拠の種類（別の分野・ほかの解法も関わる問題）を表示 |
| 異なる文脈の問題で完答・解法の想起も自己申告あり | そのうえで、主な分野以外か、ほかの解法も関わる文脈の問題で「浮かんだ」と答えた |

推薦（今日の演習）・解法カードの「違う文脈で使う」・定着度の「次にやること」は、どれも `transferTargets`（知らされずに完答した文脈と違う文脈の、主な解法の未着手問題）を使う。

### 状態

| 状態 | 基準 |
|---|---|
| 未学習 | この解法に結びつく問題をまだ解いていない |
| 要復習 | 3問以上解いて得意度 0.5 未満／一度完答した問題を直近30日に解けなかった／最後の2回が続けて完答でない |
| 習得 | 次をすべて満たす：完答4問以上・知らされずに完答2問以上・違う文脈が「異なる文脈の問題で完答」以上（判定できない解法は除く）・3日以上あけて同じ問題をもう一度完答・得意度 0.7 以上・**今も覚えている**（下） |
| 学習中 | それ以外 |

**今も覚えているか（保持）**：最後に完答した問題のうち、問題ごとの復習の記録（`pstat`）がある問題で判定する。1問以上がまだ解き直しの時期でない（R ≥ 0.9）なら「はい」、すべて過ぎていれば「すべて解き直しの時期を過ぎている」、`pstat` のある問題が1問も無ければ（古い形式の記録だけ）「確認できない」。確認できないときは習得の条件を満たさない（v0.20 では「確認できない」を満たしたとして扱っていた誤りを v0.21 で修正）。`pstat` の無い古い記録も、完答・想起・違う文脈の記録としては使う。記録は書きかえない。

得意度は、問題ごとの最後の結果を、主な解法の問題は1・補助は0.5、難しい問題ほど重く数え、0.5 へ2問分寄せた値（3問未満は出さない）。

### 基準値の確かめ（`tests/mastery.test.mjs`）

基準の数値（完答4・知らされずに2・得意度0.7）は変えていない。次の場合の判定を確かめ、どれも過大評価にならなかったため。

| 場合 | 判定 |
|---|---|
| 4問すべて主な分野 | 学習中（転用が未確認） |
| 4問のうち1問が別の分野（ほかの条件も満たす） | 習得（転用は「候補問題で完答」） |
| 解法カードを見て解いた回だけ | 学習中（知らされずに完答0） |
| 想起が未回答 | 転用は「候補問題で完答」どまり。習得の妨げにはしない |
| 別の分野の完答で「浮かばなかった」 | 転用に数えず学習中 |
| 同じ問題を12回くり返した | 学習中（完答は1問と数える） |
| 完答後に不正解 | 要復習 |
| 最後の2回が続けて完答でない | 要復習 |
| 古い記録しかない（1年後） | 学習中（今も覚えているか確かめられない） |
| ほかの解法も関わる問題だけ | 学習中（文脈が1種類） |
| 補助として結びつく問題で完答 | 転用に数えない |
| 得意度：5問中4完答／6問中4完答 | 基準内（79）／基準外（68） |

得意度 0.7 は「最後の結果がおおむね4問に3問以上完答」に当たる。完答4問は、知らされずに2問・違う2つの文脈・間をあけた再完答を同時に満たせる最小に近い数で、これより少ないと1つの問題の結果で判定が変わりやすい。

## 今日の演習の推薦（`catalog.js` の `pickToday`）

1. 復習の時期が来た問題（scheduler。忘れかけた順）——理由「前回完答できなかった問題の復習」「復習の時期」。**新しい学習の枠を最低3問（復習が1回分の4倍より多くたまっているときは2問）残す**。1つの分野の復習は1回の半分まで。残りの復習は「復習だけ」から解ける
2. 要復習の解法（その解法を主に使う未着手の問題）1問（枠が5問以上なら2問）。直近24時間にその解法の問題を解いていれば次の解法へ——「要復習の解法『…』を立て直す」
3. 未学習で、必須の前提を学び始めている解法から1問——「まだ学んでいない解法『…』を学ぶ」
4. 転用が未確認の解法を、違う文脈の問題（`transferTargets`）で1問——「『…』を別の分野の問題で使う」「『…』を、ほかの解法も関わる問題で使う」
5. 苦手分野から最大2問——「苦手な分野『…』を補う」
6. 残りは頻出度で重みをつけたランダム——「新しい問題」

復習以外は、1つの分野から1回の3分の1まで（復習と合わせて半分まで）。選んだ難易度の未着手が尽きたら、解いてから3日以上たった問題を古い順に出し、理由は「解いてから日がたった問題」と書く。条件に合う問題が足りないときは、制限を越えずに少ない数で出し、理由（選んだ難易度で出せる問題が無い／分野の上限）を今日の画面に書く。理由は選んだ規則そのものを表示する（ランダムに選んだ問題に別の理由を付けない）。

推薦の性質は `docs/simulation.md`（架空の学習者8人のストレステスト）で確かめている。
