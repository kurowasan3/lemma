# 匿名性・プライバシーの設計

方針：**登録しなくても全部の学習機能が使える**。アカウントは「複数端末で使う」「有料機能を使う」ときだけ作る。集めるのは機能に必要な最小限。

主な利用者は高校生（多くは未成年）であることを前提にする。

## 1. ゲスト利用の仕組み（現状と追加）

【確認】現状：ゲストの記録は `localStorage['lemma.v2']` だけにあり、外部へは送らない（`privacy.html` 1節、`app.js` `save()`）。外部への通信は同一オリジンの `data/` 取得だけ。

| 機能 | 現状 | 追加 |
| --- | --- | --- |
| 問題演習・オフライン | ○ | — |
| 学習履歴の端末内保存 | ○（最新5,000件） | — |
| ブックマーク | ✕ なし | `state.bookmarks = {問題ID: 付けた時刻}`。同期時は和集合＋墓標（`deleted` に `b:問題ID`） |
| バックアップ | ○ JSON 書き出し・読み込み | 読み込み時に形を検査し「合わせる／置き換える」を選ぶ（S6） |
| 端末の引き継ぎ | ファイルのみ | 引き継ぎコード（§4.2） |
| 消えにくくする | — | `navigator.storage.persist()` を、初回の解答後に1回だけ要求する |

## 2. ローカル保存の限界

| 限界 | 内容 | 対策 |
| --- | --- | --- |
| Safari の7日ルール | iOS/macOS の Safari は、**Safari で7日間そのサイトを操作しないと、localStorage・IndexedDB・Service Worker を消す**。ホーム画面に追加した Web アプリは Safari とは別に数えられ、使っていれば消えない | 「ホーム画面に追加」を案内する（既存の README の手順をアプリ内にも）。Safari で使っている利用者には、7日以上空いたらバックアップを促す表示 |
| 保存容量 | localStorage は1オリジン約5 MB【推測】（ブラウザで異なる）。記録の上限 1.1 MB なので現状は余裕がある | `log` の上限5,000件を維持。容量超過時は `save()` の例外を捕まえて警告（現状は黙って失敗する【確認】`app.js` 68行） |
| オリジンに紐づく | URL（オリジン）を変えると記録が見えなくなる | ドメイン移行は1回で済ませ、引っ越しの手段を用意（[migration-plan.md](migration-plan.md) P1） |
| ホーム画面アプリと Safari は別の保存領域（iOS） | 同じ端末でも記録が共有されない | アプリ内で「ホーム画面から開いているか」を判定し、表示を分ける |
| 端末の紛失・初期化 | 復元できない | 書き出し・引き継ぎコード・同期 |
| 共用端末 | 次の人が記録を見られる | 「この端末の記録を消す」を分かりやすく。ログアウト時に「端末の記録も消す」を選べるようにする |

## 3. アカウントへの移行

【確認】現状：ログイン直後に端末の記録とサーバーの記録が**確認なしで合算**される（`sync.js` `verify()` → `syncNow()`）。

変更：ログイン直後、両方に記録がある場合だけ選ばせる。

| 状況 | 動作 |
| --- | --- |
| 端末に記録あり・サーバーに無し（初めてのログイン） | そのまま端末の記録をアップロード（今と同じ） |
| 端末に無し・サーバーにあり | そのままダウンロード（今と同じ） |
| 両方にあり | 「この端末の記録（○問・最終○月○日）をアカウントに合わせますか？」→ **合わせる**／**この端末の記録は使わない**（端末側を書き出してから捨てる） |

共用端末で他人の記録がアカウントに混ざる事故を防ぐ。合わせ方の規則（`mergeState`）は変えない。

## 4. 匿名利用者の同期方法の選択肢

| 案 | しくみ | 開発 | 運用 | セキュリティ | 匿名性 | 復旧性 |
| --- | --- | --- | --- | --- | --- | --- |
| **① メール OTP（現行）** | メールアドレス＋数字コード | 済 | SMTP 代 | ○ | △ メールアドレスを預かる | ○ 別端末で同じメールなら戻る |
| ② Supabase 匿名サインイン | 端末ごとに名前のないユーザーを作る | 小 | MAU に数えられる | △ 大量作成の対策（CAPTCHA）が必須 | ◎ | ✕ 端末を失うと戻らない。別端末へ移すにはメールを結び付ける必要 |
| **③ 引き継ぎコード（新規）** | 端末で記録を暗号化→一時保存（24時間・1回限り）→別端末でコード入力 | 中 | ほぼ0 | ○ 鍵はコードの中にだけあり、サーバーは中身を読めない | ◎ 識別子を残さない | ○ 移す瞬間だけ |
| ④ 合言葉でエンドツーエンド暗号化した継続同期 | 合言葉から鍵を作り、暗号文だけを保存 | 大（合わせ方をサーバーで行えない、鍵の管理） | 小 | ○ | ◎ | ✕ 合言葉を忘れると全部失う |
| ⑤ ファイル書き出し（現行） | JSON をダウンロード | 済 | 0 | ○ | ◎ | ○ ファイルを保管していれば |

**推奨：①＋③＋⑤**。
- 継続的な同期・有料会員は ① に一本化する。決済には連絡先（Stripe の領収書）がどのみち要り、② は端末を失った有料会員を救えない。
- 「アカウントは作りたくないが機種変更したい」は ③ で満たす。④ は合言葉を失ったときの被害（全損）が受験生には大きすぎる。

### 4.2 引き継ぎコードの仕様（③）

```
旧端末：鍵 K（128bit）とID（64bit）を乱数で作る → AES-GCM(K, state) → Edge Function `transfer` に (ID, 暗号文) を送る
        画面にコード = base32(ID ‖ K)（約32文字。QR コードも表示）
新端末：コードを入力 → ID で暗号文を取得（取得した時点でサーバーから削除）→ K で復号 → 「合わせる／置き換える」
サーバー：transfer_codes(id, ciphertext, created_at)。24時間で自動削除（pg_cron）。1 IP あたりの作成回数を制限
```

- 暗号は Web Crypto API（ブラウザ標準）だけで書ける。ライブラリは足さない。
- サーバーは鍵を受け取らないので、運営者も中身を読めない。プライバシーポリシーにそう書ける。

## 5. データ削除

| 何を | 方法 | 現状 | 変更 |
| --- | --- | --- | --- |
| 端末の記録 | 設定 →「記録をすべて消す」 | ○ ただしログイン中は次の同期で戻る【確認】 | ログイン中は「この端末だけ」「アカウントの記録も」を選ばせ、後者は `reset_my_study`（[database-design.md](database-design.md) §5） |
| 1回分の解答 | — | ✕ | 履歴の画面から削除（墓標つき） |
| メモ（自由記述） | — | ✕ | メモの一覧から削除 |
| アカウント | 設定 →「退会する」 | ○ `delete_my_account()` で全表から削除【確認】 | 有料会員は先に購読を解約（Edge Function `account-delete` が Stripe を解約 → `delete_my_account`）。Stripe 側の顧客・請求の記録は法令上の保存のため Stripe に残る（ポリシーに明記） |
| サーバーのバックアップ | — | — | 削除後もバックアップに一定期間残る旨をポリシーに明記（保存期間は【要検証】Supabase のプラン） |

## 6. 収集データの最小化

| データ | 集めるか | 理由・扱い |
| --- | --- | --- |
| メールアドレス | 同期ユーザーのみ | ログインに必須。他の目的に使わない（メールマガジンは別途の同意がない限り送らない） |
| 学習記録 | 同期ユーザーのみ | 同期のため |
| 自由記述（メモ・詰まった所・異議） | 同期ユーザーのみ | 個人情報を書かないよう入力欄に注意書き。**同期から外す設定**を用意 |
| 氏名・学校・学年・年齢 | **集めない** | 必要がない。学年別の機能を作るときも端末内の設定にとどめる |
| IP アドレス・UA | 自分では保存しない | Supabase・Cloudflare・Stripe のログには残る（ポリシーに明記） |
| アクセス解析 | アプリ（app）では**入れない**。公開サイト（www）は Cloudflare Web Analytics（Cookie を使わない）だけ | Google Analytics は入れない |
| 広告の行動ターゲティング | www のみ。**既定で非パーソナライズ広告**を要求 | 利用者の多くが未成年のため |
| 決済情報 | 持たない | カード番号は Stripe だけが持つ。DB には Stripe の顧客ID・購読の状態だけ |

## 7. プライバシーポリシー・法令対応で必要な変更

`privacy.html`（2026-11-03 制定）の現行の記述「広告や行動追跡のための仕組みは使いません」は、広告を入れた時点で**事実と合わなくなる**。広告・決済の公開前に改定する。

追記する項目：
1. 公開サイト（www）の広告（Google AdSense）と、それにより Google が Cookie 等を使うこと、オプトアウトの方法
2. アフィリエイト（Amazon アソシエイト等）と、リンク・枠が広告であること
3. 決済（Stripe）に渡る情報と、運営者が保持する情報（顧客ID・購読の状態のみ）
4. 引き継ぎコード（暗号化され運営者は読めない・24時間で削除）
5. 委託先と保存地域（Supabase・Stripe・Cloudflare・Google）
6. 削除後のバックアップの保存期間

**要法務確認**（運営者は弁護士・専門家に確認すること。この文書は法的助言ではない）：
- 電気通信事業法の外部送信規律（2023年6月施行）の対象になるか、なる場合の公表事項
- 特定商取引法の表示と、定期購入の最終確認画面の表示事項（Stripe Checkout の画面で足りるか）
- 未成年者の契約（民法の取消権）への対応：課金前に保護者の同意を確認する文言・チェック
- 景品表示法のステルスマーケティング規制（2023年10月施行）：アフィリエイト枠・紹介文の「広告」「PR」表示
- 個人情報保護法：メールアドレスと学習記録の利用目的の公表、開示・削除請求の窓口
