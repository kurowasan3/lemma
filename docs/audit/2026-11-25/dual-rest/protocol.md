# 残り93問の解き直し手順（答えを見ずに解く）

対象: `ids.json` の93問。v0.29.2 で追加した254問のうち、入力用の答え（grading）がないもの。

この作業は、保存されている答えをまだ見ていない新しいセッションで行う。
2026-11-25 のセッションでは途中でこの93問の保存済みの答えを表示してしまったため、そのセッションでは解かない。

## 読んでよいもの・読んではいけないもの

第3段階（照合）に入るまで、次の範囲を守る。

| 区分 | 対象 |
|---|---|
| 読んでよい | このディレクトリの `problems.md`、`ids.json`、`protocol.md` |
| 読んではいけない | `content/` 以下のすべて（問題、選択肢、図、品質） |
| 読んではいけない | `data/`、`tests/golden/` |
| 読んではいけない | `docs/audit/` 以下でこのディレクトリ以外のもの |
| 読んではいけない | 問題管理表（Excel）とその書き出し |
| 読んではいけない | `git log -p`、`git show`、`git diff` など、過去の差分を表示する操作 |
| 読んではいけない | アプリの画面とビルド結果 |

- 作業はリポジトリの外の空のディレクトリで行い、`problems.md` だけをそこへ写す。
- 計算用のスクリプトもその外側のディレクトリに置く。
- `content/figures.json` は問題文中の式から自動で作るグラフ表示で、答えは含まない。それでも念のため読まない。

## 第1段階：解く

- `problems.md` の問題文だけを使って解く。
- 小問ごとに次を書く。

| 項目 | 内容 |
|---|---|
| 答え | 値、式、集合、領域、関数、個数など |
| 根拠 | 要点を1〜3行で |
| 方法 | 手計算 / SymPy / 総当たり（全ケース）/ 範囲を限った探索 / 数値計算 |
| 確信度 | 高 / 中 / 低 |

- 証明の小問は、主張が正しいかと論証の骨子を書く。
- 領域や範囲の答えでは、境界を含むか、除外点があるかを必ず明記する。
- 数値計算で見つけた候補は、できるかぎり式で導き直す。導き直せなかったものはそのことを書く。

## 第2段階：答えを確定する

- 93問すべての答えを `blind_answers.md` に書き、コミットする。
- このコミットより前に保存済みの答えを開かない。
- 確定したあとは書き換えない。誤りに気づいた場合も、照合の段階で別に記録する。

## 第3段階：照合する

照合は文字列の比較ではなく、数学的に同じかどうかで判断する。

| 答えの種類 | 確認すること |
|---|---|
| 関数 | 定義域と、すべての点での値が一致するか |
| 集合 | 要素が一致するか（包含を両方向で確認する） |
| 領域・範囲 | 境界を含むか、端点や除外点が一致するか |
| 数列 | 一般項、適用範囲（n の範囲）、初期値が一致するか |
| 証明 | 主張が正しく、保存済みの解説の論証が成り立つか |
| 数値 | 値が一致し、解析的な裏付けがあるか |

結果は `results.csv` に1行1問で書く。列は id、レベル、分類、方法、メモ。

| 分類 | 意味 |
|---|---|
| A | 解析的に導いて一致 |
| B | 数値計算や範囲を限った探索で答えを決めて一致（A と同じ強さには扱わない） |
| C | 表記や形式は違うが、数学的に同値 |
| D | 不一致。人による確認が必要 |

## 守ること

- これは AI による確認であり、人による確認として記録しない。
- `content/quality/human.json` と `quality.checks.dual` は変更しない。
- 不一致（D）が見つかっても、保存済みの答えを自動で直さない。報告して止める。
- 照合するのは答えだけである。解説の証明の正しさ、解き方が最適か、問題自体に欠陥がないかは別の監査で扱う。
