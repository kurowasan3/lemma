# v0.28.2：「主な解法なし」の明示指定と、管理表との整合の修復

件数はすべて data/techniques.json・content/problems・spec_check.csv・管理表のコピーから数えた。

## 1. 調べたこと（実装前）

- 主な解法の決め方（tools/build_app_data.py）：
  - 問題に `techniques`（管理表の「解法」列）があれば、それだけを使う。先頭が主、残りが補助。
  - 無ければタグから自動で決める。weak 以外で最初に当たった解法が主になり、当たった解法はすべて結びつく。
  - タグより「解法」列が優先する。
- 取り込み（tools/xlsx_to_content.py）は見出しの名前で「解法」列を探し、読点・カンマで分ける。この仕組みはもともとある。
- 管理表は元のファイルも復旧版も19列で、**「解法」列が無い**。指定は content にしか無かった（v0.28.1 の11問）。
- 主な解法の無い問題はアプリにすでに 1,230問あった（すべて自動）。画面・習熟・推薦はこの状態をもう扱えている。

同じ処理を2か所に書かないよう、主な解法を決める処理を `select_techniques` という1つの関数にまとめた。ビルドとテストの両方がこれを使う。まとめた直後に全問の結果（主・結びつき・`manual`）を前と比べ、まったく同じことを確かめてから変更した。

## 2. 実装した内容

| 「解法」列 | 意味 |
|---|---|
| 空欄 | 従来どおりタグから自動 |
| `主な解法なし` | 主な解法を空にする。タグから自動で主を選ばない。タグに当たる解法は補助として残る |
| `解法A、解法B` | 先頭が主、残りが補助（従来どおり） |
| `主な解法なし、解法A`（予約語が先頭でも2番目以降でも） | 誤り。tools/audit_data.py が止める。ビルドでも主は選ばない |

- **データで区別できる**：明示指定の問題は data/techniques.json の新しい項目 `nomain` に載る（今は2問）。自動で主が無い問題（1,230問）とは混ざらない。画面は `nomain` を読まないので、画面の変更は無い。
- **名前の衝突**：「主な解法なし」をカードの ID・名前・旧 ID に使うと、次の3か所で誤りになる。
  - ビルドが止まる
  - tools/audit_techniques.py
  - tools/audit_data.py
- **変えていないもの**：タグ・検索・問題の内容・学習記録は、指定しても変わらない。
- **変えたファイル**：
  - tools/build_app_data.py（`select_techniques`・`NO_MAIN`・`nomain` の書き出し）
  - tools/audit_data.py（予約語の位置と衝突の検査）
  - tools/audit_techniques.py（衝突の検査、`nomain` の問題に主が無いこと・索引にあること・名前の指定と重ならないこと、件数の表示）
  - tools/xlsx_to_content.py は変えていない（もとの分け方のまま読める）。

## 5. テスト（tests/technique_links_test.py を拡張）

- **「解法」列の読み方**：
  - 空欄は自動。
  - 主な解法なしでは主が空になり、補助は残る。自動の主も復活しない。
  - 名前の並びは従来どおり。
  - 予約語が2番目にあっても、先頭でほかと並んでいても誤り。
  - 無い名前は誤り。
  - 予約語をカード名に使うと、検査で誤りになる。
- **取り込みからの通し**：その場で作るテスト用の .xlsx（空欄・主な解法なし・名前2つ・主な解法なし＋名前）を xlsx_to_content で取り込み、解法の決定まで確かめる。CI でも動く。
- **データ全体**：
  - 主な解法は1問に1つまで。
  - 主は結びつき（ids）に含まれる。
  - `nomain` と `manual` が content の指定と一致する。
  - 指定の無い 5,195問は、タグからの自動の規則で作り直した結果と主・結びつきが一致する。
  - 指定の名前はすべてカードにある。
  - 解法の検査に誤りが無い。
- **判定の記録**：357件（v0.28.0 の126件と v0.28.1 の231件）。
- **21件**：spec_check.csv の期待どおりか。content の指定が管理表のコピーの値と同じか。件数が指定のある問題の数と合うか。
- **テストが働くことの確認**：
  - v0.28.1 のデータに戻して実行すると、26件が失敗した。
  - 予約語の処理を外したビルド関数で実行すると、読み方のテストが失敗した。
