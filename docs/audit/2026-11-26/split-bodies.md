# 問題本文の分割読み込み（v0.32.0）：調査・設計・実測

## 1. 改修前の構造（v0.31.1）

- **起動時に読むもの**：`data/index.json`（全5,470問の一覧，gzip 182KB）・`techniques.json`（54KB）・`collections.json`（1KB）。
  - 出題の選び方（今日の演習・復習・苦手分野・類題・問題セット）は，この一覧と学習記録だけで決まる。本文は使わない。
- **本文**：分野ごとの `data/f-<分野>.json`（20ファイル，計16.3MB，最大2.2MB）。
  - 中身は問題文 `q`・答え `a`・解説 `s`・核となるアイデア `k`・入力用の答え `in`・選択肢 `ch`・図 `fg`/`af`。
  - 割合は 解説59%・問題文20%・アイデア9.5%・選択肢4.9%。
  - `ensureBodies` は，演習を始める前に出題する問題の分野ファイルを丸ごと読む。
- **検索**：`data/search.json`（gzip 467KB）を初めて検索したときに読む。本文は使わない。
- **Service Worker**：コード用とデータ用のキャッシュ。どちらも「まずネットワーク」（`cache: 'no-cache'` で毎回確かめる）。
- **学習記録・想起・定着度・復習**：問題IDと記録だけで計算する。本文の置き方には依らない。

## 2. 方式の比較

ランダムな8問（300回の試行）を，サーバーと同じ gzip -6 で換算した値。

| 方式 | ファイル数 | 8問で読む量 | 要求数 | 評価 |
|---|---|---|---|---|
| 分野ごと（改修前） | 20 | 約1.5〜2.6MB | 7〜8 | 分野を混ぜるほど重い |
| 問題ごと | 5,470 | 約10KB | 8 | 最小だが，ファイル数が多すぎる（リポジトリ・配信・ブラウザからのアップロード） |
| 固定数の塊（並び順で20問ずつ） | 282 | 約130KB | 8 | 問題を非表示にすると，後ろの塊がすべてずれる |
| **番号20番ごとの塊（採用）** | 289 | 約127KB | 8 | 塊が問題IDだけで決まり，追加・非表示でほかの塊が変わらない |
| 本文と解説を分ける（解説は答え合わせのとき） | — | 最初は約4割（解説の59%をあとで） | 16 | 答え合わせの直前に通信が要り，オフラインの途中で解説が出ない恐れ。不採用 |
| 検索用の索引の分割 | — | — | — | 一覧は出題に全問ぶん要る。検索の索引は検索したときだけ読むので，今回は対象外 |

採用した理由：
- 分野を混ぜた8問は，どの方式でもほぼ8つの別ファイルに当たる。だから1ファイルを小さくするほど効く。
- 番号で決めれば，問題を足したとき変わるのは末尾の塊だけ。非表示にしたときも，その塊だけ。
- 中身のハッシュを URL に付ける（`?h=`）ので，中身が同じ塊は版が変わっても同じ URL のまま。Service Worker が「まずキャッシュ」で返せる。

## 3. 実測（ローカルの gzip サーバー，Chromium，390×844）

- 通信量は CDP の `encodedDataLength`（gzip 後に転送したバイト数）。
- 時間は「Fast 3G 相当」（1.6Mbps・150ms）に絞って測った。
- 改修前は `fix/search-id-and-subject`（v0.31.1）。

### 初回の「まず8問解いてみる」

| | 改修前 | 改修後 |
|---|---|---|
| 起動時（全体／data） | 23件 504KB ／ 3件 237KB | 23件 508KB ／ 3件 241KB（一覧に塊のハッシュ +4KB） |
| 8問の本文 | 7〜8件 1,474〜1,700KB | 8件 71〜85KB |
| 押してから1問目が出るまで（Fast 3G） | 7.9秒 | 0.9秒 |

- 8問は乱数の種を同じにしても，起動の非同期の順で別の問題になった。

### 検索

| | 改修前 | 改修後 |
|---|---|---|

## 4. 残る課題

- **検索の索引**：`search.json`（467KB）は，初めて検索したときにまとめて読む。番号・科目・分野だけの検索なら一覧で足りるので，本文の言葉で探すときだけ読むようにできる（次の候補）。
- **一覧の大きさ**：`index.json`（182KB）は出題に要るので分けていない。問題が増えれば比例して大きくなる。
- **Service Worker の切り替わり**：古い Service Worker（v0.31 以前）が動いている端末では，初回は塊を「まずネットワーク」で読む。新しい Service Worker に替わってから「まずキャッシュ」になる。動作に支障はない。
