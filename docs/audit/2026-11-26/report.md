## ⑥ 今後の改修ロードマップ（優先度順）

1. **解答の正しさの確認を回す（P1）**
   - 内容：
     - 学習者が「解説・答えがおかしい」を送れるボタンを付ける（問題ID・小問・自由記述）。送り先は Supabase の1表で，書き込みだけ許す。
     - 送られたものと，よく出題される基礎〜入試基礎の830問を人の確認の優先リストにする。
     - 確認した問題に `human: true` を付ける。
   - 効果：誤りが運営に届くようになる。何度も解く基礎・標準から正しさを保証できる。
2. **問題本文の分割読み込み（P1）**
   - 内容：本文を分野ごと1ファイルから，約50問ずつの塊（またはID範囲）に分け，`ensureBodies` は必要な塊だけ読む。
   - 効果：初回の8問で 2.8MB → 約0.3MB（gzip後）。問題を増やしても初回の重さが増えない。オフラインの事前取得の単位にも使える。
3. **弱点 → 解法 → 類題の流れを，定着度から1タップで（P2）**
   - 内容：定着度画面の「苦手な解法」から，その解法の未着手・間違えた問題で演習を始める。
   - 効果：分析の結果がそのまま次の演習になる。部品（解法カード・`pickFromIds`・類題）は揃っている。
4. **検索の仕上げ（P2）**
   - 内容：
     - 番号だけで1件に決まるときは，結果を出さず直接問題を開く。
     - 番号の0埋めを吸収する。
     - タグの候補を入力中に出す。
   - 効果：番号で開くのが最短手数になる。
5. **復習待ちの見通し（P2）**
   - 内容：今日の学習に「明日・今週の復習待ち数」を出す。何日も空けたときは，溜まった復習を分けて出す。
   - 効果：毎日の継続の目安になる（連続日数のような煽りは使わない）。
6. **CSS・app.js の整理（P2）**
   - 内容：
     - v0.30 の上書き層を本体に統合する。色は変数だけで決める。
     - app.js の画面（検索・解答後・定着度）を別ファイルに分ける。
     - 振る舞いは変えず，e2e で守る。
   - 効果：今回のような上書きによる不具合を防ぎ，変更の影響範囲を狭める。
7. **オフライン用の事前取得（P3）**
   - 内容：設定から「選んだ分野をオフライン用に保存」。2の塊を使う。
   - 効果：通学中など，電波の弱い場所でも演習できる。
8. **ライトモードの主ボタンのコントラスト・ルートの吹き出し（P3）**
   - 内容：4.27 → 4.5:1。吹き出しを押したら，閉じたうえでその下のボタンにも届かせる。

採らないもの：
- 問題数をただ増やすこと（方針に合わない）。
- 連続日数・ランキング（煽らない方針）。
- 大規模なフレームワーク移行（効果に比べて危険が大きい）。

## ⑦ 次に実施すべき改修：問題本文の分割読み込み（ロードマップ2）

- **利用者への効果**：初めての受験生が最初に触れる「8問解いてみる」で，約2.8MB（gzip後）の読み込みを待たされている。分割すると約1/10になる。復習・類題で別の分野へ移るたびに起きる待ちも減る。

  - 変えるのは `tools/build_app_data.py` の書き出し，`catalog.js` の `ensureBodies`，`sw.js` のデータのキャッシュ。

  - 「content/ から data/ を作り直すと同じ」「一覧と本文の一致」のテストがそのまま守りになる。
- **波及効果**：オフライン保存・問題の追加・検索の結果からの即時表示が軽くなる。
