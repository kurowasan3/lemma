**読み取りだけで調べた。** 問題ID・content/・data/・supabase/・js/・学習記録・ブックマーク・メモは変えていない。管理表の原本も書き換えていない。

## 1. 結論

- **アプリの ID は初回コミット（2026-11-10）から一度も付け替え・削除されていない**（Git の全コミットで確認）。
- **ずれは管理表の側で、原因は2つ。**どちらも問題内容の照合で、例外なく説明できた。
  1. **10-30 作成の問題 558問が管理表に無く、同じ分野でその後ろにあった 588問の ID が詰まっている。**
  2. **管理表2〜4の 574問は、アプリに足すときに ID を付け替えた**が、管理表には付け替える前の ID のまま入っている。
- 管理表には、アプリに未収録の 11-22 作成の問題が 254問あり、うち 190問はアプリで別の問題が使っている ID を持つ。
- 推奨：**ID の正本はアプリ**。管理表をアプリの ID に合わせる手順は `excel_migration_plan.md`、今後の運用は `id_sync_spec.md`。

## 2. 558 と 588（別の集合）

10-30 作成の問題はアプリに 1,146問ある。管理表との関係で2つに分かれる（重なりなし）。

- 558問は、各分野で 10-30 作成分の**最初の連続した番号の塊**（多くの分野で30問、B-STA・I-DAT は20問、X-MIX は8問）。例：A-COM-238〜267。
- 588問は、その後ろの 10-30 作成分。**管理表の番号＝アプリの番号 −（同じ接頭辞で、それより小さい番号の「管理表に無い」問題の数）**の規則で、588問すべての管理表の ID を説明できる（例：アプリ A-COM-268 → 管理表 A-COM-238）。
- 558問が管理表で消されたのか、最初から管理表に入らなかったのかは、データからは区別できない。分かるのは次のこと：
  - 無いのは各分野の「ひと塊」で、重複を選んで消した形ではない。管理表の全行と比べて、ほぼ同じ問題（答えも同じ）が残っているのは1問（II-CAL-235）、似た類題が残っているのは23問、残り534問には対応する問題が無い（`missing_review.csv`）。
- 前回の報告で 494・558・588 が混ざって見えたのは、(1) 558 と 588 が別の集合であることを書き分けていなかった、(2) 照合の候補の取り方が実行ごとに揺れ、G・E の境目の数問が動いていた（「494」はその途中の値）、の2つ。いまは候補を ID 順に決め、hash seed を変えても結果が同じ（§5）。

## 5. 対応関係の種類と照合の監査

| 関係 | 件数 | 説明 |
|---|---|---|
| 1対1（確定） | 4,659 | A 3,467・B 13・D 1,162・同じ ID の E 17。管理表の同じ行に確定の対応が2つあることはない |
| 1対多（アプリ1問に管理表の候補が複数） | 0 | F が無い |
| 多対一（管理表の1行にアプリの複数の問題） | 56行 | 確定の対応1つ＋E の候補（A+E 47・A+E+E 7）、または E の候補だけ（E+E 1・E+E+E+E 1）。**E の候補は「似ている行」で、対応の確定ではない** |
| 対応先の無い管理表の行 | 254 | すべて 11-22 作成。4,659 ＋ 254 ＝ 4,913 |

- **同一ID別問題 1,352**：両方にある ID 4,849 から、同じ ID の問題と対応した 3,497 を除いた数。v0.27.1 の「同じIDが別の問題 1,358」は ID ごとに問題文をそのまま比べた数で、1,352（別の問題）＋6（同じ問題の言い回し違い）。
- 照合の監査：
  - hash seed を 0・7・12345 に変えて再実行し、5つの成果物がすべて同じ。
  - 完全一致は正規化した問題文の一致。正規化は空白・`\mathrm`・`\text`・`\displaystyle`・`\dfrac`・`\left`/`\right`・全角半角の句読点・波括弧・`$` だけで、数値・演算子・条件は変えない。A と D は答え・解説も比べた。
  - **類似度で対応を確定したものは無い**（E は候補として残し、確定の対応の数に入れていない）。
  - G のうち 226問は管理表に問題文の類似 0.6 以上の行があるが、総当たりで見ると、ほとんどが同じ型の文（「最大値と最小値を求めよ」など）で数値も答えも違う別の問題。
  - 自動の区分の限界の例：II-EQ-181（G）は管理表の II-EQ-061 と文字だけ違う同じ問題（k と a）。答えの表記が違うので自動では「類題あり」になった。人が見るときは「統合の検討」に近い。

## 6. 学習記録への影響

学習記録は**問題IDだけ**で問題に結びついている（解答の記録 `log.p`、復習状態 `pstat`（reps・lapses・last・S・D）、ブックマーク、説明のメモ。習得状態と復習予定はこれらから計算する。端末・バックアップ・Supabase の `lemma_state.state` で同じ）。問題内容の照合用の値は持っていない。

- ID が消えると「今の問題データに無い問題ID」の警告になるだけで、記録は残る。
- **ID が同じまま中身が別の問題に変わると、どこでも検出されない。** いまの管理表をそのまま取り込むと 1,352 の ID がこれに当たり、558問が消える。
- サーバーの保護（guard.sql の LM007）はキーが消える書き込みを拒むので、ID を付け替える移行は通らない。**アプリの ID を変えない方針なら、学習記録の移行は不要。**
