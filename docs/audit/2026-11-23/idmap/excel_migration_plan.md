## 0. 正本の判断材料

アプリの ID に合わせれば学習記録の移行は要らない。管理表の ID に合わせると、1,162問の ID の付け替えと学習記録（端末・バックアップ・Supabase）の移行が要り、サーバーの保護（LM007）とも衝突する。

## 3. 新しい 254問の ID

ID の規則（docs/data-spec.md）：`<分野の接頭辞>-<3桁の番号>`。接頭辞は content/taxonomy.json の `idPrefix`。一度使った ID は変えない・再利用しない。

- 64問：今の ID（B-SEQ 25・III-DIF 25・X-MIX 8・C-CUR 6）はアプリが一度も使っていないので、そのまま。
- 190問：今の ID はアプリで別の問題が使っている。接頭辞ごとに、アプリ（Git の全履歴）と管理表のどちらでも使われた最大の番号の次から順に付ける（例：III-DIF-319 → III-DIF-375）。
- 254問とも、行の分野と ID の接頭辞が合っている。

## 4. 作業の手順（人が実行を決めてから）

1. 管理表の原本を別名で保存する（原本は書き換えない）。
2. 作業用のコピーで、ID の列を `excel_rename_plan.csv` の「合わせた後のID」に**行番号で**置き換える（ID で探すと、入れ替えの途中で同じ ID が2つになる）。
3. `excel_restore_plan.csv` の 558問を、content/ の内容から行として足す（「状態」の列に `要判断` と区分を書く）。
4. v0.27.0 の修正を反映する（v0.27.1 の手順と同じ。修正前と一致するセルだけ）。
5. 確かめる：`python3 tools/import_xlsx.py 作業用.xlsx --check` で、content/ と違うのが「新しい 254問が増える」だけであること。同じ ID で内容が変わる問題・消える問題が 0 であること。
6. 0 でなければ取り込まない。0 なら、新しい 254問を足すかどうかを別に決める（足すなら通常の取り込み）。
